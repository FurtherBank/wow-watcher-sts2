首次发布

1. 确认游戏验收完成，并准备好发布所使用的 Steam 账号。

保持 Steam 客户端运行且已登录。后续条目会归该账号所有。游戏使用测试分支 public-beta。

2. 刷新并核对待上传材料。

进入项目根目录后执行
python3 scripts/prepare_workshop.py

应显示名称「假如愚者是观者」、版本 0.1.4、可见性 private。
脚本检查图片体积、介绍正文、前置条目 ID 和内容目录，并复制运行文件，不会连接 Steam。
如果修改介绍，同时更新对应正文文件和 workshop.json 的 description；校验会拦截二者不一致的情况。

3. 首先上传私密条目。

只有在确认要创建 Steam 条目后，才执行下方命令。首次成功会分配新的创意工坊条目 ID。

进入官方上传器目录后执行下列命令，将路径换成实际绝对路径并保留双引号
./ModUploader upload -w "<项目目录>/workshop"

成功标志是上传器显示 Successfully uploaded，并在 workshop/ 下写入 mod_id.txt。
保存这个 ID 文件，后续更新会使用它覆盖原条目。
如果上传中断且日志已经显示创建了条目，但尚未生成 mod_id.txt，先记录日志中的条目 ID，并核对自己的创意工坊项目；使用 upload --id 原条目ID -w 工作区路径继续，避免直接重试创建重复条目。
错误日志在工具运行目录中的 mod-uploader.log。

4. 检查 Steam 页面和前置依赖。

打开上传结果对应的工坊页面。核对标题、介绍、封面、普通版和升级版截图。
Required items / 必需物品必须列出以下两个条目，不能只在介绍中放链接。

The Watcher，作者 lamali，工坊 ID 3747492505
https://steamcommunity.com/sharedfiles/filedetails/?id=3747492505

BaseLib，工坊 ID 3737335127
https://steamcommunity.com/sharedfiles/filedetails/?id=3737335127

配置已填入这两个数字 ID，官方上传器会提交依赖关系。仍需核对实际页面结果。
分类使用 Cards、Extensions，并带 Fool、Watcher 与十种语言标签。确认页面实际显示相应分类及支持语言。

5. 完成协议与版本标记。

如果 Steam 提示需要同意创意工坊协议，由账号本人阅读并处理页面提示；未完成时条目无法公开。

介绍首部已明确写出 public-beta 和已验证游戏版本 v0.113.0。
官方工具文档提示分支范围字段的行为存在异常，因此本配置未依赖 minBranch / maxBranch 自动限制。每次上传后都复查页面的版本兼容性设置，如页面提供测试分支选择，则设置为 public-beta。保留介绍首部的测试版说明，避免用户仅凭平台标签判断。

6. 通过创意工坊订阅路径验收。

完全退出游戏。
把手动安装的 mods/WowWatcher 备份并移到游戏 mods 目录之外，避免验收到本地副本。
订阅自己的私密条目，并确认同时订阅上面指定的 The Watcher 和 BaseLib；等待下载完成。
通过 Steam 启动游戏，确认三个 Mod 已启用，且实际加载来自工坊下载的本条目。

使用愚者获得并打出这张牌，验证以下体验。
名称为「哇 观者！」，哇后有一个空格。
卡图正常显示，查看大图后进入战斗、抽到该牌时不卡死。
0 费技能，稀有，带哇旋律标签，打出后消耗。
普通版生成未升级的四张牌，升级版生成四张升级牌。
四张分别是随机愤怒牌、随机平静牌、猛虎下山和渎神。
愤怒、平静随机池不包含初始牌与带消耗的姿态牌。
手牌接近满额时，多出的牌进入弃牌堆。
切换所需语言并重新进入游戏，卡名和描述正常。

现有游戏副本测试已经覆盖这些核心行为，但尚未经过 Steam 首次上传、订阅、下载的完整路径；这一环必须在条目创建后完成。

7. 改为公开并核对访客访问。

订阅安装验收完成后，在创意工坊页面把可见性从私密改为公开。
同时把本地 workshop.json 的 visibility 改为 null 或删除该字段，避免以后重新上传把条目恢复为私密。
在未登录 Steam 的浏览器窗口中仍能访问页面并看到订阅入口，才算公开流程完成。再核对必需物品、图片和描述均正常。
如果链接可打开但搜索未收录，先检查可见性、协议提示和页面审核状态，不要重新创建条目。搜索收录可能晚于直接链接可用。

后续更新

保留原来的 mod_id.txt。在源码中更新版本并完成测试，重新构建，再运行 prepare_workshop.py 刷新 content/。
编辑 change-note.txt，同时更新 workshop.json 的 changeNote。
执行同一条 upload 命令更新原条目，确认日志使用的是已存在的 ID。
上传后复查页面版本标记、必需物品和可见性。工坊的 branch 字段不可替代介绍中的测试版说明。
如果已经在网页手动编辑正文，后续上传前同步到本地材料；配置中非空的 description 会覆盖网页正文。
